## 一句话结论

FlashAttention 通过分块、跨块归一化和反向重算，**减少完整注意力计算中的显存读写，同时保留原来的数学运算。** 它抓住了一个具体机会：最终要得到输出，未必需要把所有位置之间的关系表完整存下来。

我觉得这篇最值得理解的是两件事怎样接在一起：数学上，哪些统计量足以把分块结果正确合并；系统上，怎样利用这些统计量，让数据尽量在 GPU 片上完成处理。只有“把矩阵切小”，还不足以解释它为什么算得对、又为什么能更快。

## 它想解决什么问题

注意力让一个位置参考其他位置的信息。先用查询 Q 与各位置的键 K 计算匹配分数，再用 softmax 把分数变成总和为 1 的权重，最后加权汇总值 V，得到输出。

如果序列有 N 个位置，完整的关系表有 N×N 项。长度翻倍，关系数量大致变成四倍。经典实现会先计算并保存分数表 S，再读 S、计算并保存权重表 P，最后读 P 与 V 汇总输出。训练反向还会用到中间结果，于是这些大表既占空间，又产生大量读写。（[原文 §2.2、Algorithm 0](https://arxiv.org/html/2205.14135v2#S2.SS2)）

论文重点考虑 GPU 的两层存储：HBM 是容量较大的显存；片上 SRAM 容量小、访问快，可以理解成靠近计算单元的工作区。矩阵乘法可能很擅长利用 GPU 的算力，但 softmax 等操作还要不断访问数据，整个过程的耗时不只取决于做了多少次乘加。

这就是标题里的 IO-awareness：把数据从哪里读、往哪里写，一起纳入算法设计。FlashAttention 的主方法保留完整的允许关系，寻找更省访问的执行安排。因果 mask 等原有约束仍然生效，“完整”并不意味着生成文本时可以看未来。

## 方法

### 分块与融合，先让中间结果留在片上

把 Q、K、V 按位置拆成小块。一块查询与一块键形成小块分数，接着处理归一化、汇总对应的 V，再把贡献接到已有输出里。这个局部过程可以在片上工作区完成，完整的 S、P 就不必在 HBM 中展开保存。

原论文 Algorithm 1 的外层循环载入一块 K、V，内层遍历各块 Q，使载入的数据尽量被复用。小块打分、softmax 相关处理和输出汇总，又被融合到同一个 CUDA kernel，也就是 GPU 上执行的一段程序中，减少步骤之间把中间结果写回显存的机会。

第一代算法仍会在处理各块时读写临时输出和统计量，输入也可能被多次读取。收益来自具体减少了哪些大表访问，而不能理解成整个注意力过程只读一次数据。

真正的难点随之出现：**softmax 的分母属于整行。只看到一个小块时，后面位置会给分母增加多少，还不知道。**

### 先用一组数字，说明为什么局部输出不能直接平均

下面是教学构造。一个查询参考四个允许的位置，匹配分数经过指数变换后的量取为 1、2、3、4，V 分别为 10、20、30、40。完整分母是 10，加权总量是 1×10 + 2×20 + 3×30 + 4×40 = 300，所以输出为 **300/10 = 30**。

将前两个位置分为块 A，后两个分为块 B：

| 小块 | 总份额 | 加权总量 |
| --- | ---: | ---: |
| A | 1+2 = 3 | 1×10+2×20 = 50 |
| B | 3+4 = 7 | 3×30+4×40 = 250 |

只看各自小块，输出分别是 50/3≈16.67 和 250/7≈35.71。直接平均得到约 26.19，和完整结果对不上：这样给了两块相同的影响，而它们实际占完整分母的 3/10 和 7/10。

保留总份额与加权总量就够了。先分别相加，再做除法，仍是 (50+250)/(3+7)=30。每个查询分别维护这种统计，就有机会逐块完成整行，而不保存每一个权重。

### 在线 softmax：既要合并，还要使用同一个数值参照

直接计算指数可能超出计算机的数值范围。稳定 softmax 会把每个分数都减去这一行的最大分数 m，再做指数变换。所有指数结果同时除以同一个正数，分子与分母一起缩放，最终比例不变，最大的指数结果则变成 1。

分块时，每块先看到的最大分数可能不同。为了正确合并，需要保留当前最大分数 m、在该参照下的指数总和 ℓ，以及同一尺度下尚未除以 ℓ 的加权总量 u。新块的对应统计用下标 b 表示：

![在线 softmax 合并公式：新最大值取旧块与新块最大值中的较大者，按统一参照缩放并相加 ℓ 与 u，输出为 u 除以 ℓ。](/sharker-blog/images/papers/flashattention-online-softmax.svg)

这几行式子的作用很具体：先确定共同最大分数 m′，再用两个指数系数，把新旧统计换到相同参照下，然后相加。**参照变化时，修正保存的统计量，就不需要重新取回旧块的全部分数。**

仍用刚才的数字。块 A 的原始指数量为 1、2，按自己的最大分数平移，相当于一起除以 2，得到总份额 1.5、加权总量 25。块 B 的 3、4 一起除以 4，得到总份额 1.75、加权总量 62.5。

合并时统一采用“除以 4”的尺度，块 A 原来的两项统计都再乘 1/2，块 B 保持原尺度。最终 ℓ′=1.5×1/2+1.75=2.5，u′=25×1/2+62.5=75，输出仍是 **75/2.5=30**。

这里用 u 讲解，是为了把“合并分子和分母”写清楚；原论文 Algorithm 1 直接维护已归一化的输出 O，更新时把旧输出换回相应总量再合并，两种写法等价。真实 V 通常是向量，因此 u 也会有多个分量，逐分量使用相同的归一化统计即可。（[原文 §3.1](https://arxiv.org/html/2205.14135v2#S3.SS1)）

### 反向传播需要大表时，就在片上重算对应小块

前向没有保存完整的注意力权重，反向求梯度时怎么办？保留必要输入、输出与归一化统计，需要某个中间块时，再根据 Q、K 重算分数和权重，接着计算梯度。

这使算术运算量有所增加，却避免了为反向一直保存、再读回大表。它与选择性 checkpointing 有联系，收益还依赖分块与数据访问的配合。含 dropout 时，反向重算也要恢复前向相同的随机选择；附录算法保存随机数状态来处理这个问题。

这笔交换可以理解为：用一些额外算术，换掉更多昂贵的数据搬运。它是否划算，要看实际测量。（原文 §3.1、附录 B）

### 成本要分别看：算多少、存多少、搬多少

设 N 为序列长度，d 为一个注意力头的宽度，M 为片上 SRAM 能容纳的数的个数。论文在 d≤M≤Nd 的两级存储模型中分析：经典实现的 HBM 访问量为 Θ(Nd+N²)，FlashAttention 为 Θ(N²d²/M)。Θ 表示忽略常数后的增长阶。

较大的工作区可以装入更大的块，减少重复访问。但把硬件容量 M 和头宽度 d 固定后，后一个式子仍含 N²。它描述的访问减少，不能与线性时间混为一谈。

主方法的算术量仍是 N²d 级别。省下的是 HBM 中完整的 N×N 中间表；输入、输出需要 Nd 级别的空间，行归一化统计只随 N 增长。整套训练还包含其他层、模型参数和优化器状态，因此注意力的空间收益也需要与总显存区分。（[原文 §3.2](https://arxiv.org/html/2205.14135v2#S3.SS2)）

### 实验：先看数据搬运，再看整套训练

原文图 2 左侧，在 A100 上测量 GPT-2 medium 对应配置的一次注意力前向加反向。序列长度 1024，头宽度 64，16 个头，batch size 为 64：

| 测量项 | 标准注意力 | FlashAttention |
| --- | ---: | ---: |
| 运算量（GFLOPs） | 66.6 | 75.2 |
| HBM 累计读写（GB） | 40.3 | 4.4 |
| 耗时（毫秒） | 41.7 | 7.3 |

运算量增加，累计读写大幅下降，实际耗时约减少到原来的 1/5.7。这组结果直接支撑了“多算一些，也可能更快”的动机。40.3 GB 是累计流量，表示这次运算总共读写了多少数据，并非同时占用的显存容量。（[原文图 2](https://arxiv.org/html/2205.14135v2#S3.F2)）

再看整个 GPT-2 medium 的训练。原文表 2 使用 8 张 A100：

| 实现 | 训练时间 | 验证困惑度 |
| --- | ---: | ---: |
| HuggingFace | 21.0 天 | 14.2 |
| Megatron-LM | 11.5 天 | 14.3 |
| FlashAttention 实现 | 6.9 天 | 14.3 |

困惑度衡量语言模型预测文本的不确定程度，相同评估口径下越低越好。这里分数接近，时间则缩短；附录 E.2 说明比较使用相同训练超参数、400K 步和同一验证集划分。从 21.0 天算约为 3 倍加速，从 11.5 天算则约为 1.7 倍。局部注意力和整个训练的倍数，当然也不能直接互换。（[原文表 2](https://arxiv.org/html/2205.14135v2#S4.T2)）

## 我的疑问

**exact 到底保证什么？**

它保证保留同一个数学注意力运算，而不是删去关系或换成近似计算。实际浮点运算会舍入，改变加法顺序可能带来数值差异；训练本身也有随机性，因此不能要求每一位二进制结果都一致。

**更长上下文带来的质量收益，应该怎样归因？**

原文表 4 中，FlashAttention 实现的 GPT-2 small 从 1K 上下文增加到 4K，困惑度从 18.2 降到 17.5，训练时间从 2.7 天增加到 3.6 天。后者仍比 Megatron-LM 的 1K 训练 4.7 天更快。

这条证据链是：资源效率提高，使更长上下文变得可承受；改变上下文长度后，模型可能利用更多信息。它没有单独证明，在所有条件固定时，替换同定义的注意力实现就会提高任务分数。（[原文表 4](https://arxiv.org/html/2205.14135v2#S4.T4)）

**分块与块稀疏扩展，是否在做同一件事？**

分块只是安排先后顺序，主方法仍处理所有允许的关系块；块稀疏扩展额外规定跳过哪些块，会改变参与计算的关系集合。后者可以准确计算指定稀疏模式下的注意力，但不能再把它与原本的完整稠密注意力视为同一运算。

原文 Path-X 的 16K 序列结果 61.4% 来自稠密 FlashAttention，Path-256 的 64K 结果 63.1% 来自块稀疏扩展。任务和方法都有变化，两个数字不能直接当成同一实验里性能持续提高的证据。（原文 §3.3、§4.2）

**换了基线与场景，收益还能剩多少？**

附录 E.4 与已经高度融合的 Apex FMHA 比较，长度 128 的前向加反向耗时分别为 0.27 与 0.28 毫秒，FlashAttention 略慢。省存储的价值仍在，但加速需要结合对手已经做过的优化判断。

硬件、序列长度、头宽度和是否包含反向，也都会改变结果。逐 token 生成与整段序列训练的查询规模、数据访问方式不同，不能拿训练中的倍数直接承诺生成速度。这里引用的是原论文当时的测量，不能视为当前软件版本的性能承诺。（[附录 E.4–E.6](https://arxiv.org/html/2205.14135v2#A5.SS4)）

## 值得记住的点

- **数学可以帮助找到足够的中间统计。** 保存当前参照、总份额与累计输出信息，就能正确合并小块，不必保存整行权重。
- **少存、少搬、少算是三件事。** 显存占用看同时存了多少，IO 看累计访问多少，运算量看做了多少算术；真实耗时还要测。
- **数值稳定性是算法的一部分。** 新块带来更大最大值时，必须把旧统计换到同一参照后再相加。
- **重算的代价，要与数据搬运一起算。** 增加 FLOPs 可能降低实际耗时，结果取决于硬件和数据形状。
- **读加速倍数时保留实验条件。** 比较对象、测量范围、上下文长度和任务定义，都会改变一个数字的含义。

和[上一篇 LoRA](../2026-10-20-lora/)放在一起，我更能体会数学在系统设计里的不同作用：LoRA 用低秩结构约束可学习的权重改动；FlashAttention 用可组合的归一化统计，支撑另一种完整注意力执行方式。理解这些式子怎样成立，才能进一步判断成本究竟省在哪里。
